## 1. Classification & Status Taxonomy

To eliminate ambiguity, every entry in this register is classified using one of the following strict, controlled taxonomy values:

- **VERIFIED_FROM_SOURCE_CODE:** Directly confirmed from inspected algorithmic Python, C++, or Arduino/ESP-IDF firmware source files in the local/remote robotics codebase with exact line numbers.
- **VERIFIED_FROM_CONFIGURATION:** Parameterized in audited configuration files (`controllers.yaml`, `mapper_params_online_async.yaml`, Xacro definitions, or PlatformIO/Arduino board configs).
- **DATASHEET_SPECIFICATION:** Derived directly from official manufacturer technical specifications (e.g., Slamtec A1M8 Datasheet v2.4, Espressif ESP32-WROOM-32 Datasheet v3.9).
- **VERIFIED_FROM_PROJECT_DOCUMENT:** Confirmed from verified institutional records, formal project documentation, or engineering bills of materials (BOM).
- **MEASURED_WITH_TEST_EVIDENCE:** Established via recorded, repeatable experimental logs, sensor scans, or benchmark instrumentation.
- **USER_CONFIRMED_NOT_INDEPENDENTLY_VERIFIED:** Directly asserted by the engineer from physical hardware testing but lacking public third-party or lab instrumentation logs.
- **ILLUSTRATIVE:** Conceptual diagram or UI visual representation explicitly marked as non-telemetry / non-as-built.
- **UNVERIFIED:** Claim inspected and determined to lack empirical test logs; strictly designated as unverified or removed from numerical claims.
- **REMOVED:** Historical claim permanently purged from public pages due to absence of rigorous experimental measurement.

## 4. Discrepancy & External Source Reconciliation Register

1. **Agricultural Tilling Robot Autonomy Maturity Reconciliation:**
   The portfolio previously presented the robot with claims such as "Autonomous Tilling Robot", "GPS Waypoint Guidance", and "Autonomous GPS waypoint tracking". Inspection of the authoritative repository (`JosiahSK/autonomous-tilling-robot` commit `19fe9cc2f644f2947d716eead1e7bef3d797993c`) confirms that the mechanical system is completed, throttle servo control is bench-tested, LiDAR obstacle stopping is tested at 50 cm, and GPS data acquisition is functional (`GPSNode` parsing NMEA 0183 sentences and publishing `sensor_msgs/NavSatFix`). However, autonomous waypoint following, Nav2 integration, and closed-loop steering remain active future work (Level 1-2 maturity). The portfolio has been fully updated to designate the system as an **Agricultural Tilling Robot Prototype** with **GPS Data Acquisition**, explicitly stating that autonomous path planning and Nav2 navigation are under active development.

2. **Agricultural Tilling Robot Powertrain & Battery Voltage Reconciliation:**
   The V5.3 claims register had previously listed an assumed 4S / 12.8V LiFePO4 battery pack. Inspection of the project repository reveals that `README.md` lines 37 and 42 explicitly specify a `24V LiFePO4 battery` and `Rear-wheel drive (24V DC motor)` with chain transmission. Furthermore, `docs/testing.md` line 12 records an empirical bench test: `| LiFePO4 under load | PASS - stable at 23.8V |`. This conclusively establishes a 24V nominal (~8S) LiFePO4 powertrain. The portfolio, BOM tables, and schematics have been corrected to reflect the 24V LiFePO4 power system and 24V geared DC motor chain drivetrain.

3. **Furrow Depth: Design Target vs. Measured Result:**
   The previous SVG schematic labeled `Target Furrow Depth ~15cm`. The repository contains no empirical soil furrow depth measurements; `docs/testing.md` notes that the tilling blades were verified as "Effective on soft soil", with quantitative multi-acre furrow calibration planned for future field trials. The claim has been re-labeled as `Design Target: ~15cm Furrow Depth`, preventing misinterpretation as a validated experimental metric.

4. **ESP32 Command Timeout vs. Hardware Watchdog & E-Brake:**
   In `JosiahSK/esp32-microros-2wd-car` (`firmware/esp32_microros_2wd/esp32_microros_2wd.ino`), the firmware implements `millis() - lastCmdTime > CMD_TIMEOUT_MS` (500 ms) inside `loop()`, which executes `stopMotors()` to command zero PWM on the motor driver pins. This is an application-level software command-age check rather than a hardware watchdog timer (WDT) or active electrical dynamic brake (which depends on motor driver freewheeling vs active braking characteristics). The portfolio now strictly uses "Software Command Timeout" and "500 ms Timeout → Zero PWM", completely removing references to "deterministic failsafe" and "E-Brake".

5. **Quadruped Public GitHub README Inconsistency:**
   The external repository `JosiahSK/ros2-quadruped-locomotion` historical README references "100 Hz ros2_control" and "sub-10 µs analytical IK". The repository's actual configuration file (`src/quadruped_description/config/controllers.yaml`) sets `controller_manager.update_rate: 200` and `joint_trajectory_controller.state_publish_rate: 100.0`, while `locomotion_controller_node.py` runs a 100 Hz timer loop. Furthermore, the repository lacks any latency measurement benchmark code. The portfolio strictly decouples from the external README's imprecise phrasing, presenting the verified 200 Hz manager / 100 Hz timer distinction, 100 Hz JTC controller-state topic distinction, and deterministic closed-form mathematics without fabricated latency numbers.

6. **RPLIDAR Hardware Revision Tracking:**
   The physical unit revision is not stamped in repository manifests. The portfolio therefore explicitly avoids claiming R5 capabilities (12 m) for the physical hardware, noting that A1M8-R4 is rated to 6.0 m while A1M8-R5 is rated to 12.0 m on white targets, with the software mapping stack bounding range to 8.0 m.
