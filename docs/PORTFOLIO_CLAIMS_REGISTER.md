## 1. Classification & Status Taxonomy

To eliminate ambiguity, every entry in this register is classified using one of the following strict, controlled taxonomy values:

- **VERIFIED_FROM_SOURCE_CODE:** Directly confirmed from inspected algorithmic Python, C++, or Arduino/ESP-IDF firmware source files in the local/remote robotics codebase.
- **VERIFIED_FROM_CONFIGURATION:** Parameterized in audited configuration files (`controllers.yaml`, `mapper_params_online_async.yaml`, Xacro definitions, or PlatformIO board configs).
- **DATASHEET_SPECIFICATION:** Derived directly from official manufacturer technical specifications (e.g., Slamtec A1M8 Datasheet, Espressif ESP32-WROOM-32 Datasheet).
- **VERIFIED_FROM_PROJECT_DOCUMENT:** Confirmed from verified institutional records, formal project proposals, or engineering bills of materials (BOM).
- **MEASURED_WITH_TEST_EVIDENCE:** Established via recorded, repeatable experimental logs, sensor scans, or benchmark instrumentation.
- **USER_CONFIRMED_NOT_INDEPENDENTLY_VERIFIED:** Directly asserted by the engineer but lacking public third-party or lab instrumentation logs.
- **ILLUSTRATIVE:** Conceptual diagram or UI visual representation explicitly marked as non-telemetry / non-as-built.
- **UNVERIFIED:** Claim inspected and determined to lack empirical test logs; strictly designated as unverified or removed from numerical claims.
- **REMOVED:** Historical claim permanently purged from public pages due to absence of rigorous experimental measurement.

## 3. Discrepancy & External Source Register

1. **Quadruped Public GitHub README Inconsistency:**
   The external repository `JosiahSK/ros2-quadruped-locomotion` historical README references "100 Hz ros2_control" and "sub-10 µs analytical IK". The repository's actual configuration file (`src/quadruped_description/config/controllers.yaml`) sets `controller_manager.update_rate: 200` and `joint_trajectory_controller.state_publish_rate: 100.0`, while `locomotion_controller_node.py` runs a 100 Hz timer loop. Furthermore, the repository lacks any latency measurement benchmark code. The portfolio strictly decouples from the external README's imprecise phrasing, presenting the verified 200 Hz manager / 100 Hz timer distinction, 100 Hz JTC controller-state topic distinction, and deterministic closed-form mathematics without fabricated latency numbers.

2. **RPLIDAR Hardware Revision Tracking:**
   The physical unit revision is not stamped in repository manifests. The portfolio therefore explicitly avoids claiming R5 capabilities (12 m) for the physical hardware, noting that A1M8-R4 is rated to 6.0 m while A1M8-R5 is rated to 12.0 m on white targets, with the software mapping stack bounding range to 8.0 m.

3. **ESP32 Watchdog vs. Software Timeout Distinction:**
   The firmware relies on an asynchronous timer check comparing `millis() - lastCmdTime > CMD_TIMEOUT_MS` to command motor stops upon packet loss. While functionally effective as a failsafe, this is a software command age check rather than an ESP32 hardware watchdog timer (WDT) or FreeRTOS task watchdog reset. The portfolio labels this explicitly as a "Software Command-Timeout Failsafe" to maintain rigorous embedded engineering accuracy.

4. **Agricultural Tilling Robot Field Trial vs. Prototype Validation Status:**
   The agricultural tilling prototype chassis, powertrain, and LiFePO4 battery power system have been fabricated and bench-tested, and the project was registered for YIP 7.0. However, recorded agronomic field trials and furrow depth calibration logs remain planned activities. The portfolio distinguishes fabricated prototype bench validation from experimental field trials.
